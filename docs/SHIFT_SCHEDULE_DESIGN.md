# 排班方案设计文档

## 1. 概述

本文档详细说明了 HR 考勤分析系统中排班方案的设计思路，重点解决**四班三倒**模式下**每周六、日都能安排三班全天上班**的排班逻辑。

---

## 2. 基本概念

### 2.1 班次定义

| 班次 | 班型 | 工作时间 | 说明 |
|------|------|--------|------|
| 早班 | A | 06:00-14:00 | 8小时工作 |
| 中班 | B | 14:00-22:00 | 8小时工作 |
| 夜班 | C | 22:00-06:00(次日) | 8小时工作 |
| 休息 | OFF | 全天休息 | 员工轮休 |

### 2.2 四班三倒定义

- **四班**：指四个班次的循环 (A班、B班、C班、OFF)
- **三倒**：指班次的轮换周期为 3 天，每 3 天循环一次班次变化
- **完整周期**：12 天 = 4 个班次 × 3 天

---

## 3. 排班方案设计

### 3.1 核心需求

1. ✅ 实现四班三倒的班次轮换
2. ✅ **每周六、日必须安排三班（A班、B班、C班）全天覆盖**
3. ✅ 保证人员均衡分配
4. ✅ 每个员工平均每个周期有1天休息

### 3.2 员工分组方案

采用**4个员工分组**，按周期轮转：

```
第1组 (员工1-N): A班 → B班 → C班 → OFF → (循环)
第2组 (员工1-N): B班 → C班 → OFF → A班 → (循环)
第3组 (员工1-N): C班 → OFF → A班 → B班 → (循环)
第4组 (员工1-N): OFF → A班 → B班 → C班 → (循环)
```

### 3.3 周期排班表

**12天排班周期示例（3个员工分别代表第1、2、3组）**

| 日期 | 周几 | 第1组 | 第2组 | 第3组 | 第4组 | 覆盖班数 | 说明 |
|------|------|------|------|------|------|--------|------|
| Day1 | 一   | A班  | B班  | C班  | OFF  | 3班    | ✅ 三班覆盖 |
| Day2 | 二   | A班  | B班  | C班  | OFF  | 3班    | ✅ 三班覆盖 |
| Day3 | 三   | A班  | B班  | C班  | OFF  | 3班    | ✅ 三班覆盖 |
| Day4 | 四   | B班  | C班  | OFF  | A班  | 3班    | ✅ 三班覆盖 |
| Day5 | 五   | B班  | C班  | OFF  | A班  | 3班    | ✅ 三班覆盖 |
| Day6 | **六** | **B班** | **C班** | **OFF** | **A班** | **3班** | **✅ 周六三班** |
| Day7 | **日** | **C班** | **OFF** | **A班** | **B班** | **3班** | **✅ 周日三班** |
| Day8 | 一   | C班  | OFF  | A班  | B班  | 3班    | ✅ 三班覆盖 |
| Day9 | 二   | C班  | OFF  | A班  | B班  | 3班    | ✅ 三班覆盖 |
| Day10| 三   | OFF  | A班  | B班  | C班  | 3班    | ✅ 三班覆盖 |
| Day11| 四   | OFF  | A班  | B班  | C班  | 3班    | ✅ 三班覆盖 |

**验证结果：** ✅ 所有日期都有三班覆盖，包括周末

## 4. 周末三班覆盖保证

### 4.1 关键规律

通过 4 个分组的错开安排，可以保证：

- **每个班次在每 3 天内恰好出现 3 次**（除OFF外）
- **每个分组在 12 天内每班出现 3 次，OFF出现 3 次**
- **任意连续的天数中，三个工作班次 A、B、C 都会同时出现**

### 4.2 数学证明

对于任意日期 `d`：
- 第 i 组的班次 = `Shifts[(d-1 + (i-1)*3) % 12] / 3]`

其中 `Shifts` 按照每个班次连续 3 天的模式分配：
- Days 1-3: A, B, C, OFF 的第一轮
- Days 4-6: B, C, OFF, A 的第二轮
- Days 7-9: C, OFF, A, B 的第三轮
- Days 10-12: OFF, A, B, C 的第四轮

由于 4 个分组在时间上错开 3 天，所以任意时刻都有 3 个班次出现。

## 5. 实现逻辑

### 5.1 伪代码

```pseudocode
function getShift(employee_id, date):
    # 确定员工所在分组 (0-3)
    group_id = employee_id % 4
    
    # 计算天数偏移
    total_days = calculateDaysSinceEpoch(date)
    cycle_position = (total_days + group_id * 3) % 12
    
    # 定义班次周期
    shift_cycle = [
        'A', 'A', 'A',           # Days 0-2: A班
        'B', 'B', 'B',           # Days 3-5: B班
        'C', 'C', 'C',           # Days 6-8: C班
        'OFF', 'OFF', 'OFF'      # Days 9-11: 休息
    ]
    
    return shift_cycle[cycle_position]

function checkWeekendCoverage(date):
    if date.dayOfWeek in [Saturday, Sunday]:
        shifts_on_date = []
        for group_id in 0..3:
            shift = getShift(group_id, date)
            if shift != 'OFF':
                shifts_on_date.append(shift)
        
        # 验证三班都覆盖
        return set(shifts_on_date) == {'A', 'B', 'C'}
```

### 5.2 算法特点

| 特点 | 说明 |
|------|------|
| 时间复杂度 | O(1) - 常数时间 |
| 空间复杂度 | O(1) - 无额外存储 |
| 可预测性 | 可提前计算任意日期的排班 |
| 公平性 | 所有员工班次分配完全相同 |
| 扩展性 | 易于增加或减少员工 |

## 6. 特殊情况处理

### 6.1 法定假期处理

**方案 A：调休制**
- 法定假期按照原排班执行
- 由调休补偿

**方案 B：轮流放假制**
- 在 OFF 日期安排法定假期
- 减少对排班影响

**方案 C：补班制**
- 法定假期后调整补班周期
- 通过额外班次补偿

### 6.2 员工请假处理

**规则：**
1. 事假/病假需提前 24 小时申报
2. 在 OFF 日期请假时，需协调其他员工补班
3. 跨班次请假需调整下一个周期的分组

**处理流程：**
```
请假申请 → 验证可替代人选 → 调整排班表 → 通知相关员工 → 更新系统
```

### 6.3 员工调岗

**调岗规则：**
- 在完整周期完成时执行调岗（每 12 天）
- 避免在班次中途改变分组
- 记录员工历史班次数据

## 7. 实施步骤

### 7.1 初期准备

1. **员工分组**
   - 将所有在职员工按入职日期排序
   - 分配到第 1-4 组（轮询方式）
   - 记录员工-分组对应关系

2. **基准日期设定**
   - 选择排班开始日期（如周一）
   - 从该日期开始计算周期
   - 设置系统时间基准

3. **班次时间配置**
   - A班：06:00-14:00
   - B班：14:00-22:00
   - C班：22:00-06:00(次日)
   - 配置加班、补班时间窗口

### 7.2 上线运营

1. **系统配置**
   - 在 HR 系统中导入员工分组
   - 配置班次时间、地点
   - 设置假期日期

2. **排班发布**
   - 提前 2 周发布下一周期排班
   - 员工确认签署
   - 公示公告栏

3. **数据统计**
   - 每月统计班次分布
   - 分析加班、缺勤情况
   - 生成考勤报表

## 8. 数据结构示例

### 8.1 员工排班数据表

```sql
CREATE TABLE employee_shifts (
    id INT PRIMARY KEY,
    employee_id INT,
    employee_name VARCHAR(100),
    group_id INT,  -- 0-3
    date DATE,
    shift_code VARCHAR(10),  -- 'A', 'B', 'C', 'OFF'
    shift_name VARCHAR(20),
    start_time TIME,
    end_time TIME,
    location VARCHAR(100),
    status VARCHAR(20),  -- 'normal', 'requested_leave', 'approved_leave'
    created_at TIMESTAMP,
    updated_at TIMESTAMP,
    UNIQUE(employee_id, date)
);
```

## 10. 常见问题

### Q1: 如果有 5 个员工怎么分组？

**A:** 采用 4 组轮询分配：
- 第 1-4 组各 1 人
- 第 5 个员工分配到第 1 组
- 结果：第 1、2、3、4 组分别有 2、1、1、1 人

### Q2: 如何应对突发缺员？

**A:** 
1. 立即从其他组调人
2. 更新该天的排班表
3. 在下一周期恢复正常分组
4. 被调人员在下周期享受额外休息日补偿

### Q3: 能否只用 3 个班次不用 OFF？

**A:** 不建议。原因：
- 会破坏班次均衡性
- 员工无法连续休息
- 容易导致过度劳累

### Q4: 周末加班费如何计算？

**A:** 
- 按排班班次正常工资 × 1.5倍（周末）
- 如在周末 OFF 日被调班，额外支付 2 倍工资
- 具体按公司薪资政策执行

## 11. 优势与局限

### 11.1 方案优势

✅ **完全自动化** - 无需手工计算，系统自动生成
✅ **公平透明** - 所有员工班次分配完全相同
✅ **周末保障** - 100% 保证每个周末三班覆盖
✅ **易于扩展** - 增加员工无需改变算法
✅ **快速响应** - 请假调岗处理简单高效
✅ **数据完整** - 便于后续考勤分析和统计

### 11.2 方案局限

⚠️ **固定周期** - 每 12 天循环，不易调整
⚠️ **个性化难** - 不支持员工特殊班次需求
⚠️ **学习成本** - 需要时间让员工适应新排班
